## agent-spend-cap

### Problem

People running coding agents in autonomous mode get surprise bills and have no simple way to size a worst case
before they start. One user reports a single Codex task fanning out on its own: "launch 826 parallel agents / threads
without any authorization on my side ... consuming a total of roughly USD 78,000" and says they cannot reach a human
at the vendor. A reply in that thread describes the same failure with Claude Code: "437 claude code subagents running
adversarial reviews on a tiny thing (in yolo mode). Nothing to stop it ... just setting a hard circuit breaker
spending cap isn't enough ... had to build my own stack of rules". A separate thread shows usage allowances
shrinking ("your included usage in ChatGPT Work and Codex will decrease from 20 times to 10 times"), so people have
more reason to budget runs. Evidence is one thread plus one adjacent one: thin, and the 78k case is an outlier.

### Target users

Developers who run Claude Code, Codex or similar agents unattended. First 100: Hacker News (Ask HN and Show HN
readers who commented in the threads above), r/ClaudeAI and r/ChatGPTCoding (not in the signals, so unverified as
channels), and the Claude Code and Codex GitHub discussions.

### MVP in one day

- One screen: inputs for model price per million input and output tokens (user-typed, no price feed), tokens per
  agent turn, turns per agent, number of parallel agents and number of retries or loops.
- Output: worst-case and typical cost for the run, with the 826-agent style fan-out shown next to the user's
  planned numbers. The result is a shareable URL (state in the query string, no accounts).
- Generates a copy-paste cap config for the user's own tool: a max-turns and max-subagents setting and a hook snippet
  that stops a run at a spend figure. Templates are static text, labelled as examples to check against the tool's docs.
- Everything client-side; the Worker only serves the app and `/api/health`.
- Key action for Web Analytics: "copy config" click and shared-URL visits.

### Existing alternatives

- The competition file has no budget, cost-guard or token-cap project among the recent launches or new GitHub
  projects (searched: cost, spend, budget, token, runaway). That only covers the last few weeks of launches.
- Per-vendor usage dashboards and spend limits: exist, but the 78k thread says they did not stop the run. How good
  they are today is unknown from the signals.
- Open-source tooling mentioned in the reply ("work receipts, better traces/observability"): names not given,
  unknown.

### Explicit non-goals

- No price database kept up to date; prices are typed in by the user.
- No enforcement agent or proxy; v1 only estimates and generates config text.
- No accounts, no history beyond the URL.

## dumpsys-json

### Problem

Developers who script against Android's `dumpsys` output have to hand-parse its free-text format. The same person
asked twice in a week on Software Recommendations: "Is there a program which returns the output of `dumpsys window
windows` as a JSON?" ("for easier parsing") and then the same for `dumpsys activity activities` ("I mean it's only 23
years Android exists"). Both got 0 to 1 answers. These are two questions from one asker, so this is not independent
repeated pain; it counts as a weak signal.

### Target users

Android developers, test-automation engineers and people writing adb scripts. First 100: r/androiddev, the Android
tag on Stack Overflow and Super User, and the Software Recommendations questions above (answering them with the
tool). Size of the audience beyond the asker is unknown.

### MVP in one day

- One screen: paste `dumpsys window windows` or `dumpsys activity activities` output (or drop a text file), get
  JSON back.
- Parser runs in the browser for two dumpsys sections only, with a section picker; unknown lines are kept as raw
  strings under an `unparsed` key so nothing is lost.
- Copy and download JSON buttons, plus a "copy as jq-ready" sample command line.
- Empty state with a short sample input; loading state for large pastes; works at 320px.
- Worker serves the static app and `/api/health` only. Pasted data never leaves the browser.

### Existing alternatives

- The competition file has no dumpsys or adb-output parser (searched: dumpsys, android, adb).
- Writing a custom parser or grep/awk pipelines: what the asker is doing now. Whether open-source parsers exist
  elsewhere is unknown from the signals.

### Explicit non-goals

- No live device connection (no WebUSB or adb in v1).
- Only two dumpsys sections; no other services.
- No schema guarantees across Android versions; output format is best effort.
- No accounts, no stored uploads.
