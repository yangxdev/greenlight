## skill-shelf

_Watchlist entry (best score 13/20). New this week: https://news.ycombinator.com/item?id=50426070._

### Problem

People who use coding agents pile up skill files (SKILL.md and similar) and have no good way to keep them organised or to know whether they work.

New this week (a different thread and a different person from the entry's evidence):

- "Do you systematically evaluate agent skills, either before or while using them? If so, what tools or methods do you use? Or do you mostly rely on reading the SKILL.md and trying things out?" (https://news.ycombinator.com/item?id=50426070, Ask HN, 2026-11-09, 23 points / 6 comments). It is the same question the entry waits for, in the poster's own words, in a second place and a month later. It is small: 6 comments, and the signal export has no replies to it.

Adjacent, not counted as the same problem:

- "How do you manage your AI agents' context across clients and projects?" (https://news.ycombinator.com/item?id=50403153, Ask HN, 2026-11-07, 98 / 60): "The major time cost for me is to re-explaining context and past decisions, client rules, that we already do." That is about context, not skills; see the second card.
- "Teach a browser task in chat and reuse it as a skill" (https://github.com/kirodotdev/KiroCrew/issues/35139, issues, 2026-11-11, 19 reactions): "the user still has to turn that demonstration into instructions, identify the inputs that change, and decide how to verify the result." A feature request on one project, about writing skills, not organising them.

Earlier evidence from the watchlist entry (verified by the Critic on 2026-09-30):

- https://news.ycombinator.com/item?id=49589914 (hn ask_hn, 2026-09-06, 320 / 299): "How do you find skills, keep them organised, and make sure they actually work?"
- https://news.ycombinator.com/item?id=49743049 (hn, 2026-09-17, 68 / 62): "you cannot simply switch between agents without starting over" (adjacent)
- https://news.ycombinator.com/item?id=49740105 (hn show_hn, 2026-09-17, 251 / 140): "Which agents did they use? What skills and tools had stuck or been thrown out the window?" (adjacent)

### Target users

Developers who use Claude Code, Codex or Cursor and keep a folder of SKILL.md files. They would search "validate SKILL.md", "SKILL.md linter", "check agent skill frontmatter" or "test my Claude skill". The owner doesn't post links, and whether these searches have enough volume is unknown.

### MVP

- A single page where you paste a SKILL.md or drop a skills folder; everything is parsed in the browser, with no sign-up and nothing uploaded.
- Static checks, each with a plain reason: frontmatter present with name and description, description long and specific enough to trigger, name matches the folder, file size and line count, referenced files that don't exist, and duplicate or overlapping descriptions across the skills in the folder.
- A per-folder table of every skill with its checks (pass / warn / fail), sorted by what needs fixing, plus a copyable report.
- No evaluation of whether a skill makes an agent do better: v1 only says whether the file is well formed and distinguishable from its neighbours.

### Existing alternatives

- Skillbox (https://producthunt.com/products/skillbox-5, Product Hunt, recent launch): "One library for your AI skills, synced to Claude Code, Cursor and Codex. Follow GitHub sources, review diffs, and scan each v…". It organises and syncs a library; the competition file text I read doesn't say whether it checks that a skill works. It overlaps on "organise", not on "does it work".
- Reading the SKILL.md and trying it, which is what the new thread's author describes as the default.
- Other SKILL.md validators and curated lists: unknown. The competition file only holds recent launches, and nothing else matched. The watchlist entry asks for a check of these and I couldn't do one from the files I have.

## agent-context-pack

### Problem

People who run coding agents across several clients or projects keep re-explaining the same context, decisions and rules, because each tool keeps its own memory.

- "The major time cost for me is to re-explaining context and past decisions, client rules, that we already do. To finish every tools as its own memory." Asked: how do you give context at the start of a session, how do you carry it between agents (Claude, Codex), and how do you keep clients' context apart? (https://news.ycombinator.com/item?id=50403153, Ask HN, 2026-11-07, 98 points / 60 comments)

Adjacent, not counted:

- "How do you keep up quality when you vibe-code?" (https://news.ycombinator.com/item?id=50444380, Ask HN, 2026-11-10, 36 / 36): "things are getting too complex with no central notion of behaviour definitions, which causes every bug-fixing session to feel like a game of whack-a-mole." A related complaint about missing written-down behaviour, from one person.
- The "you cannot simply switch between agents without starting over" thread in the skill-shelf entry (https://news.ycombinator.com/item?id=49743049, 2026-09-17, 68 / 62).

This is one thread with strong engagement; the export has no replies to it, so I can't say whether the commenters shared the pain or just answered. A single poster's problem is all I can quote.

### Target users

Freelancers and consultants who use more than one coding agent. They would search "share context between Claude Code and Codex", "CLAUDE.md and AGENTS.md sync", "one AGENTS.md for multiple agents" or "keep client context separate AI agent". Search volume is unknown.

### MVP

- One page, no sign-up: write a client or project's context once (rules, decisions, stack, do-nots) in a structured form, saved in the browser.
- One button exports the same content as the files each agent reads: `CLAUDE.md`, `AGENTS.md` and `.cursorrules` (or whichever formats the blueprint confirms), downloaded as a zip.
- A shareable link or file import/export so the context moves between machines without an account (storage in R2 or a downloaded file; the Architect decides).
- No agent integration and no memory of past sessions.

### Existing alternatives

- Make0 Brain OSS (https://producthunt.com/products/make0-brain, Product Hunt, recent launch): "Sync context across all your agents." Same promise, open source. I don't know its setup cost or whether it handles per-client separation.
- Agent Clan (https://producthunt.com/products/agent-clan) and axel.md (https://producthunt.com/products/axel-3) also matched my search of the competition file; I did not read what they do, so whether they overlap is unknown.
- Hand-maintained `CLAUDE.md` / `AGENTS.md` per repo, which is the baseline, with symlinks or copies between them.

- No importing from email, tickets or chat.
- No accounts, no team sharing.
