## diff-triage

_Watchlist entry (best score 13/20). New this week: https://news.ycombinator.com/item?id=49934037, https://news.ycombinator.com/item?id=49921591._

### Problem

Reviewers get AI-generated changes far larger than they can read and no longer understand what changed. The pain is
repeated by different people in different weeks.

New this week (two separate Ask HN threads, two different people):

- "It takes 5x longer to review Claude merge requests and I barely understand what I approve." and "I ride on hopes
  and dreams I might understand a changeset." (Ask HN: Is anybody producing good code with coding agents?, 2026-10-02)
- "I've turned into a full time reviewer instead. Spending the day reading, questioning and correcting AI is tiring in
  it's own specific way." (40 years of writing code. I didn't see the end coming, 2026-10-01). This one is about the
  burden of reviewing, not about diff size, so it counts as adjacent.

Verified earlier evidence (from the watchlist):

- "every PR that comes my way for review is on average ~6k lines of diff" (Lobsters Ask, 2026-09-04)
- "I have no clue how the new code works or what it changes or breaks" (Ask HN, 2026-09-09, 62 / 53)

Still missing: someone asking for a triage tool, or saying existing review tools fail at ordering a large diff.

### Target users

Senior engineers and reviewers who get large AI-written pull requests. Reachable in the Ask HN threads above,
Lobsters, and r/ExperiencedDevs (the last one is not in this week's signals, so unverified).

### MVP in one day

- Paste a unified diff (or `git diff` output) into a page. It is parsed in the browser and nothing is stored.
- Group changed files into a suggested reading order using plain heuristics, no AI: schema/config/dependency
  changes first, then public signatures, then logic, then tests, then generated or lockfile noise last.
- Per file, show a one-line summary of counts: lines added and removed, functions touched, tests touched or not.
- Flag risky patterns in added lines: removed checks, new network or shell calls, widened error handling, deleted tests.
- A "what to read first" list with checkboxes for tracking progress through the diff. State lives in the URL hash
  or local storage; the Worker only serves `/api/health`.
- Zero sign-up. Success: visits and "paste diff" actions in Cloudflare Web Analytics.

### Existing alternatives

- Reviu (Product Hunt, 2026-10): "The review app for code your agent writes", a review workspace for coding agents.
  It is an app, not a paste-and-go page. https://producthunt.com/products/reviu
- The GitHub pull request view lists files alphabetically and has no ordering by risk. (Not in the signals; from
  general knowledge, unverified.)
- AI review bots: unknown. They were not searched for in the competition file, and that is the weak point the
  watchlist already names.

### Explicit non-goals

- No AI summaries or paid API calls.
- No GitHub login, no fetching private repos, no storing diffs.
- No inline commenting or posting back to pull requests.
- No replacement for a full review tool.
