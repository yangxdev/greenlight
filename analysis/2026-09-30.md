## skill-check

### Problem

People collecting agent skill files (`SKILL.md`, `AGENTS.md`) have no easy way to tell whether a skill is well-formed or will work. The Ask HN thread has 320 points and 299 comments:

> "How do you find skills, keep them organized, and make sure they actually work? Do you keep improving them over time?"

The pain is real, but the thread text in the export is truncated. I can't quote the repeated complaints from the comments, so the detail of the pain is unknown. Related context: agent tooling is converging on shared instruction files ("Claude Code now reads AGENTS.md if there is no Claude.md", 741 points), and people are publishing skills in volume on GitHub. That is a supply signal, not a pain signal.

### Target users

Developers who write or collect skills for Claude Code, Codex and Gemini CLI. Where to reach them: the Ask HN thread itself, r/ClaudeAI, and the GitHub `agent-skills` topic. I have no signal on r/ClaudeAI size, so reachability is plausible but unverified.

### MVP in one day

- Static React tool at one screen: paste a `SKILL.md` (or drop a file) and get a checklist of findings.
- Client-side checks only: frontmatter present and parseable, `name` and `description` present, description length and specificity, file size and rough token count, broken relative links, empty sections.
- Each finding shows the line it refers to and a one-line reason.
- Shareable result via URL hash, so no accounts and no storage. The Worker only serves the static app plus `/api/health`.
- Note on measuring success: track visits and "run check" clicks in Cloudflare Web Analytics.

### Existing alternatives

- Unknown. None surfaced in the signals. Skill repos like `mikehasa/golive-skill` and `kaankiziltug/logo-design-skill` bundle their own CLIs, but nothing in the export is a general validator. Needs a search before building.
- Doing it by hand or by asking the model itself: no stated rules, nothing repeatable.

## tray-ledger

Below the cluster threshold: one source with weak engagement (score 3, 1 answer). I kept it because the request is unusually concrete and matches the "niche utility for a professional community" preference. Treat it as lower conviction than skill-check.

### Problem

A one-person microgreens grower tracks tray cycles and standing orders in a spreadsheet, and the spreadsheet lets them overwrite the wrong cell without noticing:

> "A spreadsheet lets me overwrite a harvest cell. The total still looks fine. That tray is already promised."

Requirements they list: no user account, works with no internet after install, a sow → move to light → harvest-by-weight loop on an ~11-day cycle, standing orders shown next to what is actually on the rack (promised vs sown), and export to CSV so they can leave. How many growers share this is unknown. There is one post and no repeats in the signals.

### Target users

Small-scale microgreens and market growers selling standing orders to kitchens and a weekly market. Communities: r/microgreens and market-farming forums. Neither appeared in the signals, so both are guesses.

### MVP in one day

- One main screen: a rack view listing active tray batches with sow date, expected harvest date and days left, using the ~11-day cycle as a per-crop setting.
- Add a batch (crop, tray count, sow date), then mark each stage: sow, move to light, harvest with weight.
- Standing orders as a simple list (customer, crop, quantity per week), with a promised vs sown comparison that warns when promised exceeds what is on the rack.
- Harvest records are append-only (a correction adds a new entry), which directly addresses the overwritten-cell problem.
- Data in the browser (IndexedDB or localStorage) with CSV export and import. No account. Offline use would need the approved hand-written service worker plus a web manifest, since offline after install is a stated requirement.

### Existing alternatives

- Spreadsheets: the current tool, and the source of the complaint.
- Dedicated farm or CSA software: unknown. None appeared in the signals, so I can't say what it costs or how it falls short.

### Signals / sources

- https://softwarerecs.stackexchange.com/questions/95595/offline-windows-ledger-for-a-one-person-microgreens-farm-trays-standing-order (stackexchange softwarerecs, 2026-09-18, score 3 / 1 answer)

### Explicit non-goals

- No money in and money out tracking. The request includes payments bookkeeping, and that is outside the compass no-go territory, so v1 skips it.
- No native Windows app. The request asked for a Windows desktop program, and the fixed stack means a browser app instead. That may not satisfy the asker.
- No accounts, sync or multi-user.
- No invoicing, no customer messaging.
