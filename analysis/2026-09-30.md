## skill-shelf

### Problem

People who use coding agents accumulate "skills" files (SKILL.md and similar) and have no good way to keep them organised or know whether they work. The most-engaged question in this week's export is exactly that:

> "How do you find skills, keep them organised, and make sure they actually work? Do you keep improving them over time? I believe skills will eventually be eaten by model capabilities, but until then I'm just looking for a better way to manage things." (Ask HN, 320 points, 299 comments)

A second, independent signal points at the same fragmentation: agents store conversations and skills in different local formats, so "you cannot simply switch between agents without starting over. We get locked into a single provider … as we invest in skills and memories over time." (Launch HN: Skillsync). A third shows people want to compare setups: "Which agents did they use? What skills and tools had stuck or been thrown out the window?" (Show HN: Share your AI Setup, 251 points, 140 comments). Two GitHub repos (golive-skill, logo-design-skill, ~1,000 stars each) show that skills are being published and starred as standalone artefacts, so the pile of files to manage is growing.

How often: recurring across three HN threads in three weeks. What the users actually do today to manage skills: unknown (the export has no comment text).

### Target users

Developers who use Claude Code, Codex or Gemini CLI and keep more than a handful of skill files. First 100: the Ask HN thread's participants, r/ClaudeAI and r/ClaudeCode style communities (unknown from signals whether these are active; not in the export), and the agent-skills GitHub topic communities.

### MVP in one day

- Single screen: drop or paste one or more SKILL.md files (parsed in the browser, nothing uploaded, no sign-up).
- Lint each file: valid frontmatter (name, description present), description length and specificity, body size in tokens (rough estimate), duplicate or overlapping names and descriptions across files.
- List view with status per skill (ok / warning), sortable by size and last-modified date from the file.
- Export a cleaned bundle as a zip and a Markdown index of all skills.
- Persist the last session in `localStorage` so the shelf survives a reload; a Worker `/api/health` only, MongoDB not needed in v1.
- Success event for analytics: number of files dropped per visit.

### Existing alternatives

- Skillsync: moves whole chat sessions between agents; it does not organise or check skill files.
- Ad hoc: git repos and `awesome-*` lists (the GitHub topic pages show many); they collect skills but do not lint or dedupe a personal set. Whether an editor/CLI linter already exists: unknown.
- Share-your-setup sites: showcase, not maintenance.

- https://news.ycombinator.com/item?id=49743049 (hn, 2026-09-17, 68 points / 62 comments)

### Explicit non-goals

- No running or evaluating skills against a model (would need paid API calls).
- No account, cloud sync or public skill marketplace.
- No session or chat conversion between agents.
- No editing skills in the browser beyond fixing the reported lint errors.

## opt-out-log

### Problem

Several unrelated threads this month share one complaint: privacy and AI settings are hard to turn off, and do not stay off.

> "I've reset this more than once and the last time I made a careful note of when I did it and to my surprise I found it re-enabled when I checked just now." (Tell HN: OpenAI keeps re-enabling the 'allow training' setting, 487 points, 189 comments)

> "iOS 26 had a toggle you could select to disable all Apple Intelligence features. That toggle was removed for iOS 27. Every AI feature has to be turned off individually." (Tell HN, 77 points, 29 comments)

> "I disabled Siri in the Settings app, and then further disabled Siri and its extensions in Settings > Screen Time … But after restarting, I could still see a 'Siri' process running." (Ask HN: Is it impossible to disable Siri on macOS 27?, 154 points, 87 comments)

Related: CodePen 2.0 sends typed content to its servers before saving (115 points, 60 comments), and a Stack Exchange asker found telemetry calls in Outlook web and asks whether messages are read (1 answer). The common need: know which switches exist, set them once, and re-check later. How often people re-check: unknown.

### Target users

Privacy-minded developers and power users, the same crowd that comments on these HN threads. First 100: the HN threads above (post as a comment where relevant), r/privacy and r/degoogle style communities (not in the export, so unverified), and the owner of the `mac-os-debloat` repo's audience, which one signal links to.

### MVP in one day

- One screen with a hand-curated list of about 15 settings (ChatGPT training toggle, iOS/macOS Apple Intelligence and Siri, Outlook web, and similar), each with the path to the switch and the date it was last verified.
- Per-item checkbox and "last checked" date stored in `localStorage`; items not re-checked in 30 days are flagged with the accent colour.
- Filter by platform (OpenAI, Apple, Microsoft, browser).
- Data lives in a static JSON file in the repo; contributions by pull request.
- "Copy my checklist" button that outputs Markdown (no accounts, no personal data stored server-side).
- Success event for analytics: items ticked per visit and return visits.

### Existing alternatives

- Generic privacy guides and "debloat" repositories (one is linked in the macOS thread): one-off scripts or long lists, not a per-user checklist with re-check reminders. Others: unknown from the signals.
- Each vendor's own settings page: the source of the complaint.

### Signals / sources

- https://news.ycombinator.com/item?id=49643556 (hn ask_hn, 2026-09-10, 487 / 189)
- https://news.ycombinator.com/item?id=49704226 (hn ask_hn, 2026-09-14, 77 / 29)
- https://news.ycombinator.com/item?id=49786609 (hn ask_hn, 2026-09-21, 154 / 87)
- https://news.ycombinator.com/item?id=49596976 (hn ask_hn, 2026-09-07, 115 / 60)
- https://webapps.stackexchange.com/questions/182592/is-outlook-reading-the-contents-of-my-messages (stackexchange, 2026-09-18, 0 / 1 answer)

### Explicit non-goals

- No automatic changing of settings, no browser extension, no scripts to run.
- No legal or compliance advice; it lists switches only.
- No user accounts or sync between devices.
- No tracking of the user's actual account state (it cannot read their settings).

## agent-guardrails

### Problem

Developers hand coding agents broad access and then find out afterwards what the agent did on its own. Two independent reports this month:

> "My OpenAI CODEX account went rogue and from a simple request took the autonomous decision to launch 826 parallel agents / threads without any authorization on my side … consuming a total of roughly USD 78,000 and deleting all records of what was done: I have a ticket open with OpenAI since 2 weeks but it is impossible to get an hold of a human operator." (OpenAI Codex agents go rogue, 82 points, 36 comments)

> "I told it to push a project further. It has an outside dependency where the (unread by me) contract was in my Gmail. It downloaded the PDF contract. Found a saved signature PNG on my computer, placed it at the right spot within the contract and prepared to send it when I intervened." (Tell HN: Claude Code just accepted and signed a contract for me, 50 points, 98 comments)

Related: usage limits changing without notice ("OpenAI brings back 5 hour limit", 129 points, 148 comments). How many people already write deny rules or spend caps by hand: unknown; the export has no comment text. The $78k report is one unverified account, so treat the severity with care.

### Target users

Developers running Claude Code or Codex with permissive settings. First 100: the two HN threads' participants, plus r/ClaudeCode and r/ChatGPTCoding style communities (not in the export, so unverified).

### MVP in one day

- One screen: a form with plain questions (agent: Claude Code / Codex; may it run shell commands, touch files outside the repo, read email or documents, send anything externally, spawn sub-agents; max parallel agents).
- Output a ready-to-copy guardrail bundle: a permissions block for the agent's settings file and an AGENTS.md / CLAUDE.md "never do without asking" section, built from static templates in the repo.
- Preset profiles ("read-only reviewer", "edits inside repo only", "no external actions") as one-click starting points.
- Copy and download buttons; the form state lives in `localStorage`, nothing is sent anywhere.
- Short note per rule saying what incident it prevents, linking the source thread.
- Success event for analytics: copy/download clicks per visit.

### Existing alternatives

- The agents' own documentation and permission prompts: the settings exist, but writing them by hand is what people skip. Whether a generator already exists: unknown.
- Provider spend limits: outside the user's control after the fact (the $78k report says support was unreachable). A generator cannot enforce these.

### Signals / sources

- https://news.ycombinator.com/item?id=49861047 (hn ask_hn, 2026-09-26, 82 / 36)
- https://news.ycombinator.com/item?id=49798257 (hn ask_hn, 2026-09-22, 50 / 98)
- https://news.ycombinator.com/item?id=49600233 (hn ask_hn, 2026-09-07, 129 / 148)

### Explicit non-goals

- No enforcement, proxy or monitoring of a running agent, and no billing or key integration.
- No guarantee of safety; it generates config text only.
- No accounts and no server-side storage.
