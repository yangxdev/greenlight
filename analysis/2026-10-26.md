## patch-check

### Problem

Self-hosters and people who inherit servers can't tell from their own package or container output whether a named CVE is fixed on their system. The version string on the box and the version in the advisory don't line up (backports, distro suffixes, manual builds, containers with their own packages). This week's PHP RCE (CVE-2026-109618 / CVE-2026-109619) and a Brotli CVE produced several people doing this comparison by hand:

- "Inherited a bunch of Ubuntu 20.04 legacy servers. Some on 8.3 at least… `php -v` shows PHP 8.3.3-1+ubuntu20.04.1+deb.sury.org+1… I'm guessing some one manually built 8.3 on this server. Anyone got a good step-by-step on how to patch in this case?" (Ask Ubuntu, 2026-10-21)
- "I checked the NGINX version running in my Bitwarden container and found nginx/1.31.6… I've tried updating my Bitwarden instance using the official update script, but it appears that I'm already running…" (Bitwarden forum, 2026-10-23, title: "Vulnerable NGINX Version in Bitwarden Self-Hosted?")
- "Is Nextcloud 33.0.10 Docker affected by CVE-2026-111497 (Brotli)? … Installed: 1.1.0-2+b7, Candidate: 1.1.0-2+deb13u1 … The candidate comes from Debian trixie-security." (Nextcloud forum, 2026-10-25)

Frequency: each is a one-off lookup, but it recurs with every high-profile CVE. Only 3 independent people in this export, with 0-2 replies each, so this is thin evidence, not a strong signal. Unknown: how many people ask this outside these forums.

### Target users

Self-hosters running Bitwarden, Nextcloud, Plex, mailcow, Home Assistant in Docker or on Debian/Ubuntu boxes, and solo admins who inherited legacy servers. Reachable in r/selfhosted, the Nextcloud, Bitwarden and Home Assistant forums, and Ask Ubuntu (answering questions with the tool's link). Unknown: whether those communities allow link posts.

### MVP

- One page, no sign-up: paste the output of `dpkg -l <pkg>` / `apt list --installed` / `php -v` (or type distro, release, package, version).
- The Worker queries OSV.dev (free, no key) for that ecosystem and version, and lists the CVEs that apply with "fixed in" versions.
- Optional CVE field: enter a CVE ID and get a plain "affected / fixed in <version> on <distro>" line for the pasted package.
- Paste is processed in the request and never stored.
- Links out to the distro tracker entry for each result, with the exact upgrade command.

### Existing alternatives

- Debian Security Tracker and Ubuntu CVE tracker: per-CVE pages, the user has to map their own package and suffix by hand; no paste-your-list input.
- `ubuntu-security-status` / `pro status`: local only, Ubuntu only, the inherited-server case above already shows its "update installed" output confusing a user.
- Trivy, Grype, OSV-Scanner: need CLI installation and an image or lockfile; not a quick paste-and-answer.
- assetnote/php2shell-scanner (GitHub, 919 stars, 2026-10-22, from competition file): probes one CVE on a live host, not the user's installed packages.
- Competition file has no web "paste your package list" checker. Not searched beyond that file.

### Explicit non-goals

- No scanning of live hosts or IP addresses, no exploit or PoC content.
- No accounts, no stored package lists, no alerts or monitoring.
- No remediation advice beyond linking the distro's own fix.
- No coverage of language-package ecosystems (npm, PyPI) in v1.
